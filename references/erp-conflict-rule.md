# Правило конфликта протокола и ERP (раздел 25 ТЗ)

Если протокол говорит одно, а expert-1c-erp показывает другой типовой
вариант:

- НЕ заменять протокол;
- добавить в `process_model.json` → `warnings[]`:
  ```json
  {"step": "РФ.5", "type": "protocol_vs_typical_erp", "diagram_action": "keep_protocol"}
  ```
- в схеме сохраняется сценарий протокола;
- в validation report добавить абзац:
  ```text
  Зафиксированный процесс отличается от найденного типового механизма ERP 2.5.
  Требуется отдельная функциональная проверка.
  ```

## Кеш ERP-проверок

Перед новым RAG-запросом искать ответ в `./cache/erp-facts.json`:

```json
{
  "erp25.purchase_order.purpose": {
    "query": "назначение Заказа поставщику",
    "answer_summary": "...",
    "source": "...",
    "checked_at": "2026-08-10"
  }
}
```

Не повторять одинаковые проверки между протоколами. Хранить только краткие
выводы и ссылки/идентификаторы источников — НЕ полный текст лицензионных
статей ИТС (раздел 43 ТЗ).
